# ADR-006 승인 처리의 잠금 순서와 버전 확인

## 배경

승인하면 주문 상태가 바뀌고 상품 재고가 줄어든다. 승인 취소는 반대로 재고를 되돌린다. 거래처는 같은 주문을 동시에 취소할 수도 있다. 여러 관리자가 같은 화면을 열어 둔 채 각자 처리할 수도 있다.

막아야 하는 것은 세 가지다. 재고보다 많이 승인되는 것, 같은 주문이 두 번 처리되는 것, 두 트랜잭션이 서로의 잠금을 기다리며 멈추는 것.

## 검토한 방법

1. 주문을 조회해서 상태를 확인한 뒤 바꾸기
2. 주문을 `SELECT ... FOR UPDATE`로 잠그고 상태를 확인한 뒤 바꾸기
3. 상태와 버전을 조건으로 건 UPDATE 한 번으로 바꾸고, 영향받은 행 수로 판단하기

## 결정

3번으로 했다.

```sql
UPDATE sales_order SET status = 'APPROVED', version = version + 1, approved_at = now()
 WHERE id = ? AND status = 'REQUESTED' AND version = ?
```

1번은 확인과 변경 사이에 다른 요청이 끼어들 수 있다. 2번은 맞게 동작하지만 문장이 하나 더 필요하다. 3번은 바꾸는 순간에 조건을 확인하니 끼어들 틈이 없다.

버전은 화면이 주문을 불러왔을 때의 값이다. 그 사이 다른 사람이 처리했으면 버전이 달라져서 영향받은 행이 0이 된다. 그때 다시 조회해서, 버전이 달라졌으면 "다른 사용자가 먼저 처리했다", 상태만 다르면 "지금 상태에서는 처리할 수 없다"로 구분해서 응답한다.

재고는 `stock_qty >= 주문 수량` 조건을 건 UPDATE로 줄인다. 영향받은 행이 0이면 재고 부족이고, 예외를 던져서 상태 변경까지 함께 되돌린다.

잠금 순서는 모든 처리에서 "주문 행 → 상품 행(ID 오름차순)"으로 맞췄다. 주문 하나에 상품이 여러 개일 때, 승인 A는 상품 1 → 2 순서로, 승인 B는 2 → 1 순서로 잠그면 서로 기다리게 된다.

## 결과

`ConcurrencyIntegrationTest`에서 재고 10개에 승인 20건을 동시에 보내면 정확히 10건만 승인된다. 같은 주문을 5명이 동시에 승인하면 1건만 반영되고 재고도 한 번만 줄어든다. 거래처 취소와 관리자 승인이 동시에 들어오면 주문마다 하나만 반영된다.

대신 같은 상품을 승인하는 요청은 재고 행에서 한 줄로 선다. k6로 50명이 동시에 승인했을 때 승인 응답 시간 중앙값이 733ms였다. 건당 처리 시간(약 18ms)에 줄 선 순서를 곱한 값과 비슷하다. 같은 상품에 승인이 동시에 몰리는 업무라면 재고 행을 나누거나 요청을 모아 처리하는 방식을 따로 검토해야 한다.
