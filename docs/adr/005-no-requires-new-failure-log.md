# ADR-005 정산 실패 기록을 별도 트랜잭션으로 남기지 않기

## 배경

정산 실행 이력(`settlement_run_log`)에는 처리 건수와 소요 시간을 남긴다. 실패도 같이 남기고 싶었는데, 프로시저가 실패하면 트랜잭션이 롤백되면서 이력도 같이 사라진다.

처음 설계에서는 실패 기록을 `REQUIRES_NEW`로 별도 트랜잭션에서 넣으려고 했다.

## 검토한 방법

1. 실패 기록을 `REQUIRES_NEW` 트랜잭션으로 남기기
2. 실패는 애플리케이션 로그로 남기고, 흔한 실패는 프로시저를 부르기 전에 막기

## 결정

2번으로 했다.

1번을 구현하려고 보니 문제가 있었다. 실행 이력은 정산월 행을 참조하고, 프로시저는 실행하는 동안 정산월 행을 잠근다. 처음 실행하는 달이면 그 행 자체가 아직 커밋 전이다. 이 상태에서 안쪽 트랜잭션이 정산월 행을 만들거나 참조하려고 하면, 바깥 트랜잭션이 끝나기를 기다린다. 그런데 바깥 트랜잭션은 같은 스레드에서 안쪽이 끝나기를 기다리고 있다. 서로 기다리는 상태가 되는데, DB 입장에서는 한쪽이 애플리케이션 안에서 기다리는 거라 교착으로 감지하지도 못하고 그냥 멈춘다.

## 결과

실패는 `WARN` 로그로 남기고, 사용자에게는 409와 원인 메시지를 돌려준다.

가장 흔한 실패인 "이미 마감된 달"은 서비스에서 프로시저를 부르기 전에 확인해서 친절한 메시지로 막는다. 프로시저 안의 같은 확인은 두 사람이 동시에 마감하는 경우를 위한 안전장치로 남겼다.

실행 이력 화면에는 성공한 실행만 보인다. 실패 이력까지 화면에서 보려면 정산월 행을 참조하지 않는 별도 로그 테이블을 두면 되는데, 이번 범위에서는 넣지 않았다.
