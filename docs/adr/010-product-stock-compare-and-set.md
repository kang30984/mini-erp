# ADR-010 상품 수정에서 재고는 비교 후 교체

## 배경

상품 수정 API는 화면에서 받은 재고 숫자를 그대로 덮어썼다(`stock_qty = ?`). 관리자가 재고 10개인 상품의 수정 화면을 열어 둔 사이 승인 3건으로 재고가 7이 됐는데, 단가만 바꾸고 저장하면 화면이 들고 있던 10이 다시 써진다. 승인에서 아무리 초과 판매를 막아도(ADR-006) 여기서 재고가 되살아나 초과 판매로 이어진다.

## 검토한 방법

1. 상품에 버전 칼럼을 두고 `WHERE version = ?`로 막기
2. 재고를 증감(입고 +20, 실사 조정 -2)으로만 받기
3. 상품 수정에서 재고 칼럼을 빼기
4. 재고만 비교 후 교체(compare-and-set)하기

## 결정

4번으로 했다. 수정 요청에 화면이 불러왔을 때의 재고(`baseStockQty`)를 같이 받는다.

- 재고를 바꾸지 않은 수정(이름, 단가, 상태): 재고 칼럼을 아예 건드리지 않는다
- 재고를 바꾼 수정: DB 재고가 `baseStockQty`와 같을 때만 바꾸고, 다르면 409 `STALE_STOCK`과 함께 지금 재고를 알려 준다

1번은 승인·취소·반품도 버전을 올려야 해서, 단가만 고치려던 관리자가 승인 때문에 자꾸 충돌을 만난다. 2번이 기간계다운 방향이지만 입고·조정 화면과 재고 이력 테이블이 함께 필요하다. 3번은 재고를 고칠 화면이 없어진다. 4번은 지금 화면을 그대로 쓰면서 충돌이 나야 할 때만 난다.

## 결과

`ProductAdminIntegrationTest`에서 "화면을 연 뒤 재고가 바뀌었으면 덮어쓰지 않고 409", "재고를 바꾸지 않은 수정은 성공하고 재고는 그대로"를 확인한다. 화면은 `STALE_STOCK`을 받으면 목록을 다시 불러온다.

남은 것은 재고 이력이다. 지금도 재고를 숫자로 바꾸는 것이라 언제 누가 왜 바꿨는지 남지 않는다. 실무라면 2번 방식으로 입고·조정 사유를 이력으로 남기고 `stock_qty = stock_qty + ?`로 반영해야 한다.
