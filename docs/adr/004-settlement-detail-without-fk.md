# ADR-004 정산 상세 테이블에 외래키를 두지 않기

## 배경

처음 스키마에서는 정산 상세(`settlement_detail`)가 정산월과 거래처를 외래키로 참조했다. 출고 라인 10만 건으로 정산을 돌려 보니 2초 정도 걸렸다.

정산용 인덱스를 넣어도 빨라지지 않아서, 프로시저 안의 문장을 하나씩 떼어 `EXPLAIN ANALYZE`로 봤다. 출고·반품을 읽는 조회는 0.2초 정도였다. 상세 테이블에 10만 행을 넣을 때 행마다 실행되는 외래키 확인 두 개가 실행 시간의 절반 이상을 차지하고 있었다.

## 검토한 방법

1. 외래키를 그대로 두기
2. 외래키를 `DEFERRABLE`로 바꿔서 커밋할 때 확인하기
3. 상세 테이블의 외래키를 빼고, 정합성은 프로시저가 맞추기

## 결정

3번으로 했다.

2번은 확인 시점만 뒤로 미룰 뿐 행마다 확인하는 건 같아서 시간이 줄지 않는다.

상세 테이블은 `run_settlement` 프로시저만 만드는 파생 데이터다. 실행할 때마다 해당 월을 지우고 다시 만들고, 값은 이미 외래키가 걸린 원본(주문, 정산월)에서만 가져온다. 외래키를 빼도 잘못된 참조가 들어올 경로가 없다.

## 결과

같은 데이터에서 정산 시간이 2.27초에서 1.16초로 약 49% 줄었다 (Intel i3-1315U, 8GB 노트북, Docker Desktop PostgreSQL 16).

거래처별 합계 테이블(`settlement`)은 행이 거래처 수만큼(수백 건)이라 외래키 확인 비용이 작아서 그대로 뒀다.

상세 테이블을 누군가 SQL로 직접 고치면 DB가 막아 주지 않는다. 테이블 주석에 프로시저가 정합성을 책임진다고 적어 뒀고, 마이그레이션(`V5`)에 측정 근거를 남겼다.
